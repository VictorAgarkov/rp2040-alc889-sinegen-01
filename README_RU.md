# Демонстрационный проект - интерфейс HDA-Link на RP2040

## О проекте

Данный проект демонстрирует возможность использования аудиокодеков с интерфейсом HDA-Link (например, **ALC889**) совместно с микроконтроллером RP2040 и его сопроцессорами PIO.

Для реализации интерфейса HDA-Link задействованы четыре конечных автомата (SM) с номерами от 0 до 3. 

В этом проекте они выполняют следующие функции:

| SM | Назначение |
|----|------------|
| 0  | выход **SDOUT**|
| 1  | выход **SYNC** |
| 2  | вход **SDIN**, и выходы **BCLK** и сигнала начала кадра (SoF)|
| 3  | обнаружение запроса адреса кодеком и назначение адреса|

После окончания фазы запроса и назначения адреса кодеку (возвращения из функции `hdal_codec_reset()`) **SM3** может быть остановлена `hdal_release_sm_CAD()` и использована для других целей.

**Назначение выводов RP2040:**
| RP2040 Pin | Signal      | ALC889 Pin | Note  |
|------------|-------------|------------|-------|
|     4      | SoF         |     -      | Debug |
|     5      | BCLK        |     6      |       |
|     6      | SDOUT       |     8      |       |
|     7      | SYNC        |    10      |       |
|     8      | SDIN        |     5      |       |
|     9      | RST         |    11      |       |
|    13      | DBGPIN1     |            | Debug |
|    14      | DBGPIN2     |            | Debug |
|    15      | DBGPIN3     |            | Debug |
|    16      | DBGPIN4     |            | Debug |
|    17      | DBGPIN5     |            | Debug |
|    20      | UART_TX_PIN |            |       |
|    21      | UART_RX_PIN |            |       |


Проект поддерживает все частоты дискретизации, поддерживаемые данным кодеком: 44,1; 48; 88,2; 96; 176,4 и 192 кГц.

По умолчанию используется максимально возможная частота 192кГц. Это определено в **config.h**:
```c
#define HDA_SAMPLERATE 192000
```
и может быть изменено на поддерживаемую кодеком частоту в Герцах.

В качестве демонстрации проект использует все 10 аудиовыходов для генерации независимых синусоидальных сигналов. Частоты задаются в массиве `gen_freq[10]`. Для режима 192 кГц частоты каналов с 0-го по 7-й изменяются в соответствии с геометрической прогрессией с множителем 1.5 - от 880 Гц (0,004583333333 × 192 000) до 15035,6 Гц; частоты каналов 8 и 9 равны 63936 Гц и 76800 Гц соответственно.

Принятые от АЦП данные испольуются для управления светодиодом: если на любом входе есть сигнал, светик мигает, в противном случае горит постоянно.

## Как это работает

Обмен данными между PIO и ОЗУ МК происходит при помощи нескольких каналов DMA. На каждую линию (SDIN, SDOUT и SYNC) выделены по 2 канала DMA для работы с двойными программными буферами ("качели" или "пинг-понг"). Итого использованы 6 каналов DMA.

Принятые от АЦП по линии SDIN аудиоданные попадают в двойной буфер `HDA_din_buff`, после чего програмно распаковываются в набор 32-битных отсчётов в двойной буфер `g_SamplesInBuff32`. После удачной распаковки глобальный указатель `g_SamplesInBuff32_ready` принимает ненулевое значение, которое указывает на начало порции данных, и которое нужно отслеживать в основном цикле. Получив это, можно обрабатывать принятые от АЦП данные и обнулить сам указатель.

Для работы с аудиоданными для вывода на ЦАПы нужно отслеживать состояние указателя `g_SamplesOutBuff32_empty`, который может быть NULL или указывать на часть буфера `g_SamplesOutBuff32`. Как только он принимает ненулевое значение, 32-битные отсчёты для ЦАП нужно положить по этому адресу и обнулить сам указатель. В следующем кадре данные будут програмно упакованы в двойной буфер `HDA_dout_buff` и переданы наружу.

Все 32-битные значения семплов являются знаковыми (int32_t) и выровнены влево. Младшие 8 или 16 бит (в зависимости от режима кодека), либо будут отброшены (для ЦАП), либо заполнены 0 (для АЦП).

Для вывода SYNC используются два разных буфера - `HDA_sync_buff_actual` и `HDA_sync_buff_empty`. Их содержимое обновляется в процессе инициализации, и во время основной работы неизменно. Буфер `HDA_sync_buff_actual` содержит информацию об аудиопотоках (их номера и моменты начала) для кодека.  Буфер `HDA_sync_buff_empty` содержит "пустой" (не содержащий информации об аудиопотоках) сигнал и нужен, что бы иногда вставлять пустые кадры на частотах дискретизации, кратных 44.1 кГц. 

Программная работа по обработке прерываний от DMA, в т.ч. упаковка/распаковка аудиоданных, осуществляется на ядре #1, оставляя основному ядру #0 ресурсы для обработки сигналов.

## Как использовать

Для начала нужно определиться с количеством каналов ЦАП, АЦП и частотой дискретизации, и задать нужные значения в **config.h**:
```c
#define HDA_DAC_NUM    5      // number of stereo DAC
#define HDA_ADC_NUM    3      // number of stereo ADC
#define HDA_SAMPLERATE 192000 // working samplerate
```
Для вывода сигналов в ЦАП: периодически в main loop оправшиваем переменную `g_SamplesOutBuff32_empty`, и если она не NULL - подготавливаем очередную порцию (кадр) аудиоданных:

```c
if(g_SamplesOutBuff32_empty)
{
	// буфер ЦАП пуст - готовим очередную порцию семплов
	int32_t *dst = (int32_t*)g_SamplesOutBuff32_empty;
	g_SamplesOutBuff32_empty = NULL;

	// генерим выход
	make_next_sine(dst); 
}
```
Для приёма сигнала с АЦП: опрашиваем переменную `g_SamplesInBuff32_ready`, и как только она стала ненулевой - обрабатываем принятые данные

```c
if(g_SamplesInBuff32_ready)
{
	// здесь нужно обработать принятые от АЦП данные
	int32_t *src = (int32_t*)g_SamplesInBuff32_ready;
	g_SamplesInBuff32_ready = NULL;
}
```


## Сборка из исходного кода
Процедура сборки из исходного кода аналогична той, что применяется для большинства проектов на базе RP2040. Предварительно должны быть установлены все необходимые для этого пакеты.

Клонирование и сборка:
```bash
git clone https://github.com/VictorAgarkov/rp2040-alc889-sinegen-01
cd rp2040-alc889-sinegen-01
cmake . -B build
make -j 8 -C build
```
Файлы прошивки (например, *rp2040-alc889-sinegen-01.uf2*) будут созданы в директории `build`.
